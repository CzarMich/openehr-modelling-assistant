# Worked workflow: neonatal admission draft

This is a modelling demonstration, not a clinical specification. Clinical requirements, archetype selection and terminology require qualified review. No invented clinical node or code should enter a released model.

1. Create `neonatal-care` with `model_project_create`. Save requirements under `requirements/neonatal-admission.json`, with stable IDs, descriptions, priorities and unresolved questions. Record that birth weight and reflex examination require discovery and clinical review; do not declare coverage yet.
2. Call `ckm_sources`, select a configured CKM, search with `ckm_archetype_search`, and retrieve candidates with `ckm_archetype_get`. Read the returned definition, actual node paths and provenance. Select a COMPOSITION and direct ENTRY archetypes only when the source supports the intended use. A missing neonatal reflex candidate remains an explicit modelling gap.
3. Call `template_build_oet` using the retrieved identifiers. It returns a draft OET and provenance. This generator supports direct ENTRY placement only; use a qualified external modeller for nested slots, exclusions, cardinalities and native terminology constraints. Save the returned XML, sources and unresolved decisions through `model_artifact_save`.
4. Retrieve the current artifact/revision before edits. A client may propose revised XML using the template design/review prompt and source guides. Run `model_validate` and `model_diff`, then save with `expectedRevision`. A stale revision is rejected. There is no arbitrary native template edit engine in this build.
5. For coded fields, discover candidates in the configured terminology system and use `terminology_lookup`, `terminology_validate_code` and bounded `terminology_expand`. Store explicit value-set references and binding records under `terminology/`. Run `terminology_binding_validate`; missing version, node resolution or native preservation remains unresolved. Local demonstration codes use an organisation-specific URI.
6. Save explicit requirement links naming artifact, actual node/path, rationale, coverage classification and test/binding references. `model_requirements_coverage` reports declared coverage. Merely saving a template does not satisfy a requirement. Record excluded requirements with reasons and keep partial/unresolved items visible.
7. Draft AQL with the existing design/review prompt and actual template paths. Save it under `aql/`. `model_qa` does not execute AQL or compile OPT and records those missing stages. A CDR is optional and no query results are fabricated.
8. Save validation reports, structural/terminology diffs, decision records and `terminology_manifest` with the draft. Obtain external deterministic compilation/validation and independent human clinical/modelling review before release. This build has no approval/release endpoint and never marks this demonstration deployable.
